# E23 — anchor-first packing без gold

**Итог: маленький координатный прирост, default не менять.** На всём dev CER RU остался55/71, EN вырос60/71→61/71; улучшение только FR050 EN, регрессий CER нет. Предварительный gate для обсуждения будущей generation выполнен, но это не доказательство улучшения ответов или обобщения. ## Что изменили

Контроль E21 `174a45eee3c243e2a7bf21be9ddd7bae`; прежние E15 top50 `b8b229800f4246d090eea03a4d5c9900`, reranker scores, source chunks, corpus, tokenizer и B2048. Ровно один кандидат, без policy grid и последующего подбора по scores.

`pack_anchor_first_context(documents, successors, budget, count_tokens)` принимает только ранжированные документы, общие связи соседства, бюджет и счётчик токенов. **Не принимает question, scenario ID, reference или required evidence. Веса модели не обучались.** Gold доступен evaluator только после выбора контекста, для измерения.

В отличие от E21 (predecessor → anchor → successor перед greedy packing), E23 пытается принять anchor до соседей. Каждая попытка проверяет токены целой предлагаемой строки; принятые документы не вытесняются. В отображении текущей группы принятому predecessor возвращается место перед anchor. Рекурсии/новых кандидатов/обрезания чанков нет. Если anchor не влез, его соседи всё равно рассматриваются. Все подробности зафиксированы в протоколе до scores, без исключений для конкретных вопросов.

- В E21 predecessor `23b5043e1ade...`, PDF136, исходный reranker rank19/score1.4996, поднят перед anchor; он вошёл в бюджет, а anchor получил `token_budget`.

**Смысловое ограничение:** E21 уже содержал chunk `c8f6a83d4d2b...`, PDF182 (изменения Law14), с тем же правилом случайного касания и повтора, и пояснение Circular№31. ## Решение

Сохранить E23 экспериментальным вариантом, **не менять CLI/default и не объявлять улучшение качества ответов**. Получен один небольшой ожидаемый прирост canonical coverage на многократно просмотренном dev, причём альтернативное основание уже было доступно. Этого недостаточно для вывода об обобщении и немедленного платного generation-прогона. Новый подбор policy по этим scores или настройка на test в этом цикле не выполнялись.

Дальнейшая работа должна различать смысловую достаточность и canonical coverage; для проверки генерации нужны согласованные критерии существенных решений/последствий и независимая проверка спорных ответов. Старые runs, отрицательный smoke и контроль E21 сохранены.
