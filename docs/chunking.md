# Baseline-чанкинг

## Назначение

Создать единицы для будущего embedding и retrieval. Чанкер читает `cleaned-pages.jsonl`, разделяет текст каждой страницы и пишет `chunks.jsonl`. Qdrant, embedding-модель и LLM на этом этапе не вызываются.

Используется отдельный пакет `langchain-text-splitters==1.1.3`. Полный LangChain и LangGraph напрямую не добавляются; `langchain-core` и `langsmith` устанавливаются как транзитивные зависимости splitter. Подключения к сервису LangSmith здесь нет.

## Алгоритм

`RecursiveCharacterTextSplitter` сначала пробует границы блоков (`\n\n`), затем строк (`\n`), затем `. `, `! `, `? `, пробел и в последнюю очередь отдельные символы. Разделитель сохраняется в конце фрагмента. Разбиение по пунктуации эвристическое: сокращения не распознаются специальным языковым анализатором.

Начальные параметры:

| Параметр | Значение |
|---|---|
| Стратегия | `recursive_character` |
| Максимальный размер | 1000 символов Python Unicode |
| Целевой overlap | 150 символов |
| Границы страниц | Не пересекаются |
| Языки | Одинаковый алгоритм для RU и EN |

Это **символы, не токены**. Количество токенов зависит от tokenizer embedding-модели, который ещё не выбран. Overlap — целевая величина: splitter сохраняет целые доступные части текста, поэтому фактическое перекрытие может быть меньше или отсутствовать. Ограничение размера проверяется для каждого чанка.

Пустые страницы пропускаются. Остальной текст, включая короткие заголовки и фрагменты таблиц, пока сохраняется. Их фильтрация будет отдельным экспериментом. Разбиение зависит только от документов и конфигурации; вопросы и ответы evaluation dataset не используются для построения чанков.

## Координаты и метаданные

Каждый чанк содержит:

- `chunk_id`: SHA-256 идентификатора документа, хеша PDF, страницы, версии очистки, конфигурации, позиций и текста чанка. Повторный запуск на тех же данных даёт те же ID; изменение параметров меняет ID.
- `text`: фрагмент очищенной страницы.
- `document_id`, `edition`, `language`, `publisher`, `source_url`, `source_sha256`.
- `pdf_page` и `printed_page`: физическая страница PDF и распознанный печатный номер; второй может быть `null`.
- `cleaned_start`, `cleaned_end`: диапазон `[start, end)` в `cleaned_text`.
- `source_spans`: точные диапазоны `[start, end)` в исходном `text` этой же страницы.
- `cleaning_version`, `cleaning_flags`, `chunking`: версия/ограничения очистки и полная конфигурация splitter.

При очистке меняются пробелы, переносы и отступы списков, поэтому два вида координат не взаимозаменяемы. Мы строим карту непробельных символов: очищенный символ → позиция в исходном `text`. Проверяем совпадение символов, учитываем удалённый мягкий перенос U+00AD и после разбиения обрезаем карту по фактическим границам чанка. Удалённые колонтитулы не попадают в диапазоны. Пробельные промежутки могут объединяться в один диапазон, удалённый содержательный текст — нет.

Это нужно для оценки retrieval: диапазоны evidence заданы в исходном `text`, и найденные чанки можно сопоставить с ними независимо от стратегии разбиения. Критерий достаточного покрытия evidence для релевантности предстоит определить при реализации оценки; простое пересечение не объявляется правильным ответом.

Проверяются согласованность блоков с `cleaned_text`, порядок и границы исходных диапазонов, размер чанков, корректность координат splitter и покрытие всего непробельного очищенного текста. Ошибки останавливают обработку до записи результата. Запись JSONL атомарная, перезапись входного файла запрещена.

## Запуск и воспроизводимость

```powershell
uv sync --locked
uv run football-rules chunk
uv run football-rules chunk --chunk-size 600 --chunk-overlap 100 --output data/processed/chunks-600-100.jsonl
```

Ограничения параметров: `chunk_size > 0`, `0 <= chunk_overlap < chunk_size`. Команда печатает JSON-отчёт с конфигурацией, SHA-256 входа/выхода и статистикой. Параметры также сохраняются внутри каждого чанка; версии пакетов закреплены в `uv.lock`. Сам корпус исключён из Git, его можно восстановить командами ingestion → clean → chunk при наличии PDF.

Функция `chunk_corpus` возвращает отчёт как словарь: при подключении MLflow его параметры, статистику и артефакты можно будет логировать в run. MLflow на этом этапе ещё не подключён. Качество стратегий будем сравнивать после появления retrieval на dev-наборе при фиксированных остальных компонентах; test-набор для выбора параметров не используется.

## Результат baseline на корпусе 2026/27

| Показатель | Результат |
|---|---:|
| Входные страницы | 514 |
| Пустые после очистки | 63 |
| Чанки EN | 384 |
| Чанки RU | 389 |
| Всего чанков | 773 |
| Длина: минимум / медиана / максимум | 5 / 739 / 999 символов |
| Чанки короче 100 символов | 79 |

SHA-256 входного `cleaned-pages.jsonl`: `7cea405ef76c0939833b41566180690503d23ef71d89155b7c405893a7baa261`.

SHA-256 baseline `chunks.jsonl`: `160affca3f09408aae7b147d44d9e388cc7419c6c89994b324ca8885c832d105`.

На всех страницах проверены точность source ranges, совпадение содержательных символов чанка с источником, полное покрытие очищенного текста и уникальность ID. Для 67 evidence units dev-набора проверены 141 диапазон: весь их текст, оставшийся после зарегистрированных удалений очистки, покрывается чанками. Это проверка целостности, не Recall@K: поиска пока нет. Она также не утверждает, что evidence целиком лежит внутри одного чанка.

## Примеры

Первый чанк EN PDF 98 / печатная 98 имеет 621 символ. Начало:

```text
• a goal may be scored directly against the opponents from the kick-off; if the ball directly enters the kicker’s goal, a corner kick is awarded to the opponents

Offences and sanctions

If the player taking the kick-off touches the ball again before it has touched another player, an indirect free kick, or for a handball offence, a direct free kick, is awarded.
```

Аналогичный первый чанк RU PDF 100 / печатная 98 имеет 693 символа. Начало:

```text
• гол может быть забит в ворота соперников непосредственно с начального удара; если мяч непосредственно попадает в ворота команды, игрок которой выполняет начальный удар, назначается угловой удар

Нарушения и наказания

Если игрок, выполняющий начальный удар, коснется мяча снова до того, как мяч коснется другого игрока, назначается свободный удар или штрафной удар в случае нарушения при игре рукой в мяч.
```

Это выдержки, не полные чанки. Их полные исходные диапазоны — EN `[3, 615)`, RU `[3, 687)` в соответствующем поле `text`. Длины очищенного текста и исходного диапазона различаются из-за форматирования.

## Ограничения и следующий этап

- Один чанк может включать соседние разделы, а условие и исключение могут оказаться в разных чанках. Название Law/section автоматически не присваивается.
- Правило, продолжающееся на следующей странице, пока разделено границей страницы. Overlap между страницами отсутствует.
- Короткие чанки, оглавление, служебный текст, таблицы и подписи к схемам остаются в корпусе. Их присутствие может ухудшать retrieval; влияние пока не измерено.
- Структура таблиц и смысл изображений не восстанавливаются; ограничения ingestion/cleaning сохраняются.
- RU и EN могут иметь разное число токенов при одинаковом количестве символов. Лимиты embedding-модели нужно проверить перед индексацией.

Следующий этап — embedding-модель, локальный Qdrant и первый dense retrieval. Затем оценка на dev и MLflow. Только после измерения baseline можно сравнивать размеры, overlap, границы страниц и другие стратегии.

Официальное описание алгоритма: [RecursiveCharacterTextSplitter](https://docs.langchain.com/oss/python/integrations/splitters/recursive_text_splitter).
