# Журнал генерации и оценки ответов

Опыты хранятся в том же MLflow experiment `football-rules-retrieval`, с тегом `stage=generation` и ссылкой `retrieval_run_id`. Это позволяет связать ответы с конкретным retrieval, но сравнивать их следует по метрикам своего этапа. `run_kind=pilot` не равен полной оценке dev/test.

## G0 — Gemini Flash-Lite на сохранённых контекстах E10

Дата: 24.10.2026. Ветка: `experiment/generation-baseline`.

**Цель:** проверить генерацию, цитирование и пригодность автоматических оценщиков до масштабного сравнения retrieval-вариантов. Это первая контрольная точка генерации; изменения к предыдущему generation baseline отсутствуют.

**Выборка:** FR001/FR005/FR009/FR055/FR085/FR094, RU и EN — 12 ответов. Обычные вопросы и известные сложные случаи выбраны для диагностики, не случайно и не репрезентативно. FR085 — недостаточно определённый эпизод, остальные — answerable. Out-of-scope не включены. Test не использован. Эталоны созданы агентом и сверены с источниками; независимой судейской проверки нет.

### Как используется retrieval

Контроль E10 `b50e71e2d39d4145ae2f7e08fd49416e`: Qwen Dense50 + BM2550 → RRF60/top50 → greedy context, бюджет 2048 по BGE-токенизатору. В G0 повторного поиска и новых embeddings нет: читаются точные `context.text` и `context.documents` из сохранённых результатов E10. Их совпадение проверено по всем 12 вопросам.

Gemini получает только вопрос, язык, системный промпт и сохранённый контекст. Эталон, must_include/must_not_claim и gold evidence в prompt ответчика не передаются. Прежний бюджет относится к тексту источников с подписями; системный промпт/вопрос/JSON-схема — дополнительные токены Google, поэтому фактический input не равен BGE 2048.

Ответ структурирован: `status=answered|insufficient_context|needs_clarification`, `answer`, `citations`. Ссылка имеет вид `document_id:pdf_page`; PDF-страницы отсчитываются с 1. Все фрагменты указанной страницы, реально присутствующие в контексте, считаются цитируемым контекстом. Это ссылки на страницы для ответа целиком, не разметка каждой пары claim/citation.

### Конфигурация и метрики

Ответчик и оценщик: `gemini-2.5-flash-lite`, temperature=0. Лимит ответа 1024, оценщика 2048 выходных токенов. SDK `google-genai==2.33.0`; Ragas `0.4.3`, Instructor `1.17.0` с extra `google-genai`. `langchain-community==0.4.1` закреплён: в 0.4.2 отсутствует legacy VertexAI-модуль, импортируемый этой версией Ragas. Для collection metrics используется асинхронный Instructor-клиент Google, с отдельным клиентом/event loop на одну оценку. Ключ читается из окружения или локального `.env`, не включается в артефакты.

| Проверка | Что измеряет | Реализация и ограничения |
|---|---|---|
| Factual Correctness | Совпадение утверждений ответа с эталоном | Ragas FactualCorrectness, F1, default low atomicity/coverage; это не доля полностью правильных решений. Короткий эталон может штрафовать дополнительные верные объяснения. |
| Context Faithfulness | Поддержка утверждений найденными фрагментами | Ragas Faithfulness; стандартный NLI видит контекст без вопроса. Применение нормы к фактам эпизода может получать ложные штрафы. |
| Citation Validity | Есть ли непустой уникальный набор ссылок только на страницы из контекста | Детерминированный код. Не проверяет смысл ссылки; пустой список оценивается как false независимо от статуса. Это диагностическая метрика наличия и допустимости ссылок, не оценка корректного отказа. |
| Cited Context Faithfulness | Поддержка ответа совокупностью процитированных страниц | Тот же Ragas Faithfulness на подмножестве контекста. Недопустимые/пустые ссылки дают 0. Не полноценная Citation Accuracy по отдельным утверждениям. |

[Определение Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/), [FactualCorrectness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/factual_correctness/). Это предварительные LLM-суждения одной и той же моделью, возможны общие ошибки и вариативность даже при temperature=0. Answer Relevancy, полноценная claim-level Citation Accuracy, проверка must_include/must_not_claim отдельным domain judge и Correct Abstention Rate пока не реализованы. Ожидания must_include/must_not_claim сохраняются для ручного разбора, но текущий FactualCorrectness использует только reference.

Это оценка по usage, не проверка списания/баланса; smoke-run сюда не включены.

### Разбор ошибок: ответчик и оценщик

Разбор выполнен coding agent, без независимого эксперта. Источники проверки — исходные reference/must_include/must_not_claim, фактически переданные тексты и сырые суждения оценщика. Автоматические числа не заменялись ручными оценками.

- **FR001 EN:** решение «мяч остаётся в игре» соответствует эталону, нужная страница 101 присутствует, CER=1. Faithfulness=0. Оценщик превратил дизъюнкцию условий в два отдельных «only when» и отверг факты эпизода, которых нет в книге правил. В самом ответе слово «only» также создаёт риск излишнего обобщения: документ содержит и другие случаи выхода из игры. Ноль нельзя трактовать как полностью неверное решение.
- **FR055 RU/EN:** решение об угловом при ударе от ворот непосредственно в свои ворота соответствует эталону; FactualCorrectness=0 в обоих языках. Это явный повод проверить разбиение условий/контекст сравнения и калибровать оценщика. Ручной разбор не доказывает безупречность всех формулировок.
- **FR009 RU:** E10 CER=0, в ответе обычный пас ногой вратарю ошибочно назван намеренным трюком; правильное возобновление соседствует с лишними утверждениями о санкциях. Здесь проблема реального ответа. Неполный контекст — возможная причина, но причинность требует отдельного сравнения с исправленным контекстом.
- **FR094 EN:** CER=1, ответ сначала отрицает запрещённый пас назад, а затем назначает свободный удар. Противоречие при наличии нужного evidence — ошибка генерации, которую замена retrieval сама по себе не гарантирует устранить.
- **FR055 RU:** модель указала `ifab-2026-27-ru:149`, но переданный фрагмент был на PDF-странице 151 с напечатанным номером 149. Проверка по PDF-координатам правильно пометила ссылку недопустимой. **Исправление разбора 25.10.2026:** ранее здесь ошибочно был указан FR094 RU; его ссылки на страницы 120/125 присутствуют в контексте и допустимы. Исходные ответы и метрики G0 не менялись.
- **FR085 RU/EN:** статус needs_clarification выбран в обоих языках. Однако дополнительные рассуждения о совместных нарушениях не следуют из условий вопроса; правильный статус не гарантирует качественного содержания.

Cited faithfulness EN выше полной context faithfulness, хотя оценивается подмножество тех же источников: это ещё один сигнал нестабильности автоматического оценивания. Сырые утверждения/NLI и usage доступны в `judgments/`; `analysis/readback-and-usage.json` подтверждает совпадение retrieval inputs и число оценок.

**Решение:** не ранжировать E10/E13/E14 и не улучшать prompt ради текущих чисел. Сначала откалибровать проверку на небольшом наборе верных/неверных ответов и отдельно учитывать факты вопроса, вывод из нормы, противоречия и существенные условия. Затем сравнивать frozen contexts при одинаковом ответчике/промпте; если слабый retrieval вызывает ошибку — возвращаться к нему. Test, E13/E14 generation, live retrieval + generation и Ragas Answer Relevancy в G0 не запускались.

Проверки: 105 тестов / 1099 subtests; Ruff `src scripts tests`, Black `src` и затронутых script/test, strict mypy 14 модулей `src`. Readback подтвердил 12 точных контекстов E10, 36 оценок, usage и FINISHED. Ответы сохраняются сразу после API-вызова, до запуска оценщиков, чтобы не терять их при последующей ошибке.


## G1 — контроль поведения при отсутствии доказательств

Дата: 25.10.2026. Ветка: `experiment/context-grounding-control`.

**Вопрос:** соблюдает ли Gemini прежний запрет отвечать по памяти, когда источники не поддерживают решение? Prompt/model/generation config G0 не менялись. Наличие правильного ответа при пустом контексте не доказывает внутренний источник знания, но конкретное решение без источников нарушает наш контракт.

### Дизайн и подготовка

Те же 6 ситуаций RU/EN, 12 вопросов. Четыре условия, всего 48 записей:

- `original`: 12 точных ответов G0 `aaf7ea28d5bf459db7271fbbf8cdd970` повторно использованы как сохранённый контроль, без API-вызовов. Это не новый одновременный запуск контроля.
- `empty`: пустой CONTEXT, исходный вопрос и промпт.
- `removed_evidence`: непустое подмножество исходного E10-контекста, в котором оставлены только просмотренные фрагменты, не поддерживающие целевое решение. Исходный порядок и payload сохранены; все страницы required gold evidence исключены, включая их другие чанки. Это консервативное удаление многих чанков, не точечное удаление одного предложения.
- `irrelevant`: один проверенный чанк той же редакции и языка о технической зоне/флагштоках: EN PDF49, RU PDF48. Он не содержит правил, необходимых для наших вопросов.

Gold используется только при подготовке вмешательства, не передаётся Gemini и не участвует в retrieval. Оставшийся текст полностью просмотрен coding agent до вызовов. Это не независимая экспертная проверка. Размеры контекстов различаются; опыт проверяет ограничение по источникам, не скорость поиска или пользу конкретного объёма текста.

| Ситуация | Оставленные PDF-страницы RU / EN | Тема оставшегося текста |
|---|---|---|
| FR001 | 244 / 56 | Офсайд / замена дефектного мяча |
| FR005 | 22 / 142 | Процедура замены / задержка вбрасывания |
| FR009 | 112 / 137 | Умышленная игра при офсайде / нарушения при пенальти |
| FR055 | 244 / 136 | Офсайд / нарушения при пенальти |
| FR085 | 244 / 233 | Иллюстрации офсайда |
| FR094 | 112 / 110 | Умышленная игра при офсайде |

Исходный E10 имел полное gold-покрытие только в 7/12 вопросах: FR001 RU/EN, FR005 RU, FR009 EN, FR055 RU/EN, FR094 EN. Только эти 7 считаем чистыми парами «evidence присутствовало → удалено». Остальные 5 изначально неполны и не подтверждают эффект удаления из достаточного контекста. Полные тексты вмешательств и eligibility сохранены в `preparation.json`.

### Проверки поведения

Ragas и другие LLM judges не использовались. Native MLflow scorers проверяют:

1. `declares_insufficient_context`: выбрана ли эта метка в отрицательном условии. Для original — N/A, ожидание отказа не назначается.
2. `citations_within_context`: каждая указанная ссылка уникальна и присутствует в переданных страницах. Пустые ссылки допустимы; это другая метрика, чем требующий непустых ссылок G0 Citation Validity.

Содержательная проверка выполнена отдельно coding agent по всем 36 новым ответам. `definite_unsupported_ruling` — решение по эпизоду или условные исходы без подтверждения. `unsupported_rule_claim` также включает неподтверждённый нормативный критерий/порог внутри отказа. Статус needs_clarification/insufficient_context не освобождает текст от проверки. Разметка и обоснования доступны в `analysis/manual-review-and-validation.json`; это исследовательские метки, не независимый benchmark и не откалиброванный Correct Abstention Rate.

**G1 pilot:** `13bca0d6da334de58f200846cac3fbbf`, FINISHED, 48 записей, 36 новых запросов Gemini и 12 сохранённых G0. Native evaluation ~37 с. `gemini-2.5-flash-lite`, temperature=0, max output1024; исходный prompt hash совпал с G0. Веса провайдера не закреплены отдельной ревизией; по одному ответу на условие, без повторного stochastic benchmark.

### Показательные ошибки

- **FR005 RU/EN, empty:** оба ответа возвращаются к шестисекундному пределу и свободному удару, хотя вопрос явно задаёт 2026/27. В G0 основное решение было угловым. Это наблюдаемый риск отсутствия актуальных источников; внутренний механизм возникновения старого правила не установлен.
- **FR005 EN, removed evidence:** модель назначила свободный за старые шесть секунд и сослалась на переданную страницу 142. На странице говорится о задержке вбрасывания. Ссылка существует, но не подтверждает решение.
- **FR094 RU, removed evidence:** модель использовала критерии «умышленной игры» из офсайда для объяснения разрешённой игры вратаря руками. Релевантный по словам текст может провоцировать неверное применение нормы.
- **FR085 RU, empty:** модель пишет, что нужно уточнить влияние вратаря, а затем назначает повтор и при наличии, и при отсутствии влияния. Статус уточнения не предотвращает ошибочное решение.
- **FR001 RU, irrelevant:** статус отказа, но в тексте уже назван критерий полного пересечения линии, которого нет в контексте.
- **FR005 EN, irrelevant:** отказ содержит шестисекундный порог, отсутствующий и в вопросе, и в тексте технической зоны.
- **FR005 RU, removed evidence:** ссылка использует напечатанную страницу 20 вместо переданной PDF-страницы 22. Это повторяет тип ошибки G0 FR055 RU.

При пустом CONTEXT придуманы document_id `itab...`/`IFAB...` и страницы, которых модель не получала. Считать правильное по сути решение надёжным RAG-ответом здесь нельзя. Также в четырёх новых RU-ответах модель перешла на английский: FR001/FR009/FR055 removed evidence и FR055 irrelevant.

### Стоимость, проверки и решение

36 новых вызовов: input **14 347**, output+thinking **3 092** токена. При тех же проверенных Standard text rates $0.10/$0.40 за миллион [Google pricing](https://ai.google.dev/gemini-api/docs/pricing#gemini-2.5-flash-lite) оценка **$0.00267**, без smoke и повторной оплаты original G0. Это расчёт по usage, не проверка списания.

108 тестов / 1107 subtests, Ruff `src scripts tests`, Black `src` и затронутых script/test, strict mypy 15 модулей `src` прошли. Readback подтвердил 48 результатов, 12 точно переиспользованных G0, совпадение входов/контекстов/prompt hash и наличие ответов. Удаление не меняет текст/порядок оставшихся чанков и запрещает сохранение gold-страницы. Источники, корпус и gold не редактировались.

**Вывод:** текущая инструкция ненадёжна при пустом контексте на обоих языках. Отсутствие ответа по источникам — самостоятельный failure mode, отдельный от CER/правильности решения. Даже при статусе отказа нужна проверка текста; допустимая ссылка не доказывает семантическую поддержку.

**Следующий шаг:** при пустом контексте возвращать детерминированный отказ без LLM; затем отдельно сравнить текущий и более строгий prompt на замороженных условиях, проверяя существенные утверждения/ссылки и отказ без добавления правил по памяти. Защитный код и новый prompt в G1 ещё не внедрялись, чтобы не менять условия посреди опыта. Test, генерация E13/E14 и автоматический LLM-судья не запускались.


## G2 — отказ без LLM при пустом контексте и строгий prompt

Дата: 25.10.2026. Ветка: `experiment/strict-grounded-generation`.

**Гипотеза:** детерминированный guard устранит ответы без источников, а более строгая инструкция уменьшит неподтверждённые выводы в непустом контексте, сохранив полезность обычных ответов. Это два вмешательства с разной областью действия: empty проверяет guard, остальные условия — новый prompt. Эффект guard нельзя приписывать prompt.

### Реализация и фиксация условий

`generate_answer` теперь по умолчанию проверяет `context.strip()`. Если источников нет, возвращает localized insufficient_context, пустые ссылки, `api_called=false`, нулевой token usage, `model_version=null`. Вызова Google нет. Для воспроизведения старого G1 существует явный экспериментальный bypass `guard_empty_context=False`; режим `--policy original` использует его намеренно. Обычный генератор по умолчанию защищён.

`GROUNDED_PROMPT` отделяет факты эпизода от источника правил, требует проверить применимость нормы к действию/возобновлению, запрещает пороги/санкции/исходы внутри отказа, ограничивает дополнительные пояснения и требует PDF-координаты вместо printed_page. Schema и параметры ответов прежние. Новый prompt доступен через `--policy strict`, но не выбран default после наблюдаемых регрессий. `SYSTEM_PROMPT` G0 сохранён.

Все 48 inputs/expectations/context documents и preparation полностью совпали с G1 `13bca0d6da334de58f200846cac3fbbf`. Gold/corpus/retrieval не менялись. В G2 исходные контексты также получили новые ответы: 12 empty обработаны кодом, остальные 36 — новые вызовы Gemini. Сохранённые original-ответы G1 происходят из G0; это не одновременные повторные запросы baseline. Модель остаётся alias `gemini-2.5-flash-lite`, temperature0, output1024; по одному ответу на условие, выводы описательные, без закрепления весов провайдера.

Smoke: `898ec0d15dcf4c9182de72224ce161a9`, 3 случая. Трасса `tr-482b950a90577e5e3d128b1333097ef8` проверена по непустому контексту до evaluation, LLM spans присутствуют. Отдельно проверен guard-only CLI с `--limit 1 --verify-trace`: run `133cb70b656446b7afa38fe3d1c3d82d`, trace `tr-1f9a8930b6424fa2745ddbae4b74068f`, только CHAIN/RETRIEVER без LLM, успешный отказ и нулевой usage.

**Full pilot:** `689a6dae0f6648e09d9573f83d575f47`, FINISHED, 48 записей; native evaluation ~35 с. Ragas/LLM judges не использованы. Для содержательного разбора сохранены те же определения, что в G1; reviewer — coding agent, не независимый эксперт.

### Проверки, стоимость и решение

110 тестов / 1109 subtests, Ruff `src scripts tests`, Black `src` и затронутых script/test, strict mypy 15 модулей `src`. Mock-тесты подтверждают отсутствие API при пустом/whitespace контексте для RU/EN, forwarding нового prompt и явный legacy bypass. Дополнительно проверен реальный guard-only CLI. Readback подтвердил 48 тех же inputs/контекстов, отсутствие переиспользования G0 в G2, 36 API-ответов, 12 отказов без API/usage и hash prompt.

36 вызовов: input **45 735**, output+thinking **2 719** токенов; оценка по прежним Standard text rates [Google](https://ai.google.dev/gemini-api/docs/pricing#gemini-2.5-flash-lite) **$0.00566**, без smoke. Это расчёт usage, не фактическое списание. Manual annotations, сравнения, diagnostic parsing и проверки сохранены в `analysis/comparison-and-review.json`.

**Решение:** оставить empty-context guard по умолчанию; новый строгий prompt сохранить измеренной экспериментальной альтернативой, не продвигать в default. Следующее изменение должно адресовать наблюдаемые проблемы: структурированные поля источников/допустимые ID вместо свободной строки цитирования, проверка поддержки существенных утверждений и калибровка оценщика. Отдельно проверять правильность применения нормы, отказ и язык; общий статус/средний score недостаточны. Test, E13/E14 generation и новый цикл настройки retrieval здесь не запускались.


## G3 — четыре Ragas-метрики на сохранённых ответах

Дата: 25.10.2026. Ветка: `experiment/ragas-four-metrics`.

**Цель:** дополнить оценку Context Precision, Context Recall, Faithfulness и Answer Relevancy и проверить, какие ошибки они различают. Новых ответов футбольного ассистента, поиска и индексации нет: используются 12 снимков G0 и все 48 снимков G2, всего 60 записей для 12 уникальных вопросов с языком. Это отдельная переоценка фиксированных ответов, не новый эксперимент генерации и не расширение test.

### Конфигурация и значения метрик

Ragas `0.4.3`, современный collections API, judge `gemini-2.5-flash-lite`, temperature0, max output2048, Instructor async Google. Стандартные prompt-шаблоны Ragas не изменялись и не адаптировались отдельно для RU. Общий адаптер судьи выделен в `ragas_evaluation.py`; прежний G0 evaluator использует его через совместимый MetricResult. Исторические G0/G2 ответы/метрики не перезаписывались.

- **Context Precision:** вариант с reference; отдельный verdict полезности каждого фрагмента и average precision по их исходному порядку. Это не доля правильных ответов и не просто процент релевантных чанков. Оцениваются упакованные документы, реально переданные генератору, не весь pool50. [Ragas Context Precision](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/).
- **Context Recall:** доля утверждений reference, которые judge относит к контексту. Не равна нашему детерминированному Evidence Recall/CER по координатам источников. [Ragas Context Recall](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/).
- **Faithfulness:** стандартная проверка утверждений ответа по контексту, без добавления вопроса в NLI-контекст. Известное ограничение с фактами эпизода и разбиением условий сохраняется. [Ragas Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/).
- **Answer Relevancy:** strictness3, три обратных вопроса из ответа и cosine similarity к исходному вопросу с обработкой noncommittal flags по установленной реализации. Это связь ответа с вопросом, не правильность решения. [Ragas Answer Relevancy](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/answer_relevance/).

Для Answer Relevancy используется локальный BGE-M3, revision `5617a9f61b028005a4858fdac845db406aefb181`, 1024-d normalized, CPU FP32 / 4 threads / batch4. Переиспользован проектный BGEEmbedder с проверкой закреплённых файлов; исходный и обратные вопросы кодируются симметрично. Новых моделей/embeddings API нет. Модель embeddings и strictness влияют на шкалу Relevancy, поэтому сравнение выполняется при одинаковой конфигурации.

Context Precision/Recall зависят от question/reference/контекста, а не от сгенерированного ответа. Для идентичных входов G0/G2 результат переиспользован явно. Ключ кеша включает входы, порядок фрагментов, модель/config, Ragas version, embedding manifest и hash адаптера. Raw ответы judge и computed_in_run_id сохранены. Это фиксированные суждения, не независимые повторные измерения.

### Применимость и воспроизводимость

Пустой список контекстов не принимается CP/CR/Faithfulness установленной версии. Для 12 empty-кейсов каждая из этих метрик — **N/A**, не искусственный ноль. Answer Relevancy вычислена для всех записей, включая отказы; её нулевое значение для корректного отказа не объявляется ошибкой. При NaN адаптер сохраняет undefined без подмены нулём; при API/схемной ошибке invocation отмечается как ошибка, полный запуск завершается неуспешно. Здесь undefined/API errors не возникли.

Native MLflow dataset содержит исходные outputs, `mlflow.genai.evaluate` выполняется без predict_fn. Каждая метрика сохраняется вместе с applicability, cache_key/reused, сырыми суждениями и provenance. Разрезы source/condition/language/status, valid/N/A counts и answered-only means находятся в summary, метриках и таблице `group-results.json`.

**Smoke:** `16d83d22cb344763b5d7680f78a51206`, 3 записи, 12 метрик. Трасса `tr-8b8da2803bf830d1ce3e01950f742741` проверена до evaluation: ragas_context_recall CHAIN → AsyncModels LLM spans. **Полный G3:** `9d3a95d45f4a4a3a89055b773f5fb396`, FINISHED, native evaluation **5 мин 41 с** плюс подготовка.

Все **240 invocations** учтены: CP 48 numeric / 12 N/A, CR 48 / 12, Faithfulness 48 / 12, Answer Relevancy 60 numeric. 36 invocations используют кеш, включая результаты smoke и одинаковые контексты G0/G2. Всего 180 уникальных суждений метрик. Один такой расчёт может требовать нескольких API-вызовов.

## G4 — выбор ссылок из ограниченного набора source IDs

Дата: 25.10.2026. Ветка: `experiment/constrained-citations`.

**Проблема:** G0 смешивал PDF/printed_page (FR055 RU), G2 часто копировал подпись источника целиком вместо формата ссылки. Увеличение строгости инструкции не решило качество ответов. **Гипотеза:** убрать создание номеров страниц из обязанностей модели, сохранив baseline-поведение ответа. Это опыт формата цитирования, не улучшение retrieval.

### Изменение и контроль

`generate_answer(..., citation_documents=...)` создаёт один ID S1/S2/... на уникальную пару document_id/pdf_page в порядке первого появления в фактически переданном контексте. Карта SOURCE_IDS добавляется к сообщению; исходные фрагменты/подписи не редактируются. JSON schema ограничивает элементы citations enum-списком допустимых IDs. После ответа код проверяет наличие каждого ID в карте и отсутствие дубликатов, затем переводит их в `document_id:pdf_page`. Сохраняются raw выбранные `citation_source_ids` и `citation_source_map`. Неизвестные/повторные IDs вызывают ошибку без догадок, исправления страниц и скрытого повторного запроса.

Базовая часть SYSTEM_PROMPT G0 до инструкции цитирования сохранена; изменён только блок выбора ссылок, включая запрет встраивать их в текст ответа. `SOURCE_ID_PROMPT` сохранён отдельно. Строгий GROUNDED_PROMPT G2 не используется. Тем не менее schema/инструкция/список ID меняют вход модели и могут изменить сам ответ — это измеряется, а не считается безопасным предположением. Источники остаются на уровне страниц, не individual claims. Формат и принадлежность не доказывают семантическую поддержку.
