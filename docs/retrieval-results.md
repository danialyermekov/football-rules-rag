Основной MLflow experiment: `football-rules-retrieval`. Локальный backend: `data/mlflow/mlflow.db`. [План опытов](retrieval-experiments.md), [определения v2](retrieval-evaluation-v2.md).

## E0 — dense baseline с оценкой объединённых evidence

**Цель:** зафиксировать контроль для последующих опытов, не менять метод поиска. [Выборочный аудит разметки](evidence-audit-e0.md): 12 ситуаций / 24 языковые версии. Датасет не изменён.

**Конфигурация:** BGE-M3 ревизии `5617a9f61b028005a4858fdac845db406aefb181`, 1024-d normalized embeddings, cosine, фильтр языка, Qdrant Local, коллекция `football_a71631f65a6ba8bd0978b14e`, 773 чанка. Recursive splitter 1000/150 символов, без перехода между страницами. CPU float32 / 4 потока. CUDA-сборка PyTorch не установлена, GPU для E0 не использовался.

**Оценка:** `evidence_union_v2.0.0`, 142 вопроса / 71 dev-ситуация, по 71 вопросу RU и EN. Все locators обязательных evidence соединены AND, threshold 80%, дополнительно strict 100%. Бюджет 2048 токенов tokenizer BGE-M3 включает подписи источников; целые чанки, пропуск не поместившихся, без обрезания. Это не Gemini token usage.

**Full run:** `7c739293e3284f39833421cc9b8f400a`, статус `FINISHED`. Основная native evaluation — около 86 секунд; отдельный расчёт дополнительных диагностик и запись артефактов заняли дополнительное время и не входят в задержку запроса.

**Подтверждённый dry run:** `a452efe5d19b4285a42508796cdf77ec`, 3 вопроса. Прочитана трасса `tr-9afcb550903326986ebfe14cf6bb0bf7`: CHAIN, RETRIEVER, EMBEDDING и context packing. Более ранний dry run `fcf68f8e42ad4dc7a4a24fee32d16401` относится к промежуточной подготовке датасета и не используется как контроль.

### Проверки сохранённого результата

- Из MLflow повторно прочитаны 142 записи, статус FINISHED, 71 уникальная ситуация и по 50 кандидатов.
- Все основные контексты укладываются в 2048, а диагностические — в свои бюджеты.
- Сохранённые per-question оценки совпадают со средними native scorer в MLflow.
- Покрытие пула монотонно при расширении 10 → 20 → 50; числовые offsets из другой страницы/документа не смешиваются.
- Native dataset v2 не содержит chunk IDs в gold; его смысловые входы не зависят от разбиения.
- Валидатор исходных хешей/диапазонов датасета прошёл. 65 тестов, Ruff/Black и strict mypy прошли. Coverage нового модуля оценивания — 100% строк; это не доказательство качества retrieval. Два прежних предупреждения зависимостей SQLite/SQLAlchemy не подавлялись.

### Вывод и решение

E0 принят как **контроль v2**, а не как улучшение относительно v1. Основные направления следующего опыта: повысить доступность evidence в кандидатах через lexical/hybrid и проверить порядок/упаковку. Для reranker сначала нужен CPU/GPU smoke benchmark и сравнение с dense на точно таком же размере пула. Текущие кандидаты показывают запас, но не обещают величину выигрыша.

Gold содержит широкие фрагменты и неполные альтернативы. CER означает полноту этих размеченных текстов, а не экспертно подтверждённую минимальную достаточность ответа. Test, Gemini, Ragas, BM25 и reranker в E0 не запускались.

## E1 — самостоятельный BM25

**Гипотеза:** точные термины и числа могут помочь lexical-поиску там, где dense ранжирует выше близкие по смыслу фрагменты. Сравниваем отдельный метод, без fusion и reranker. Контроль — E0 `7c739293e3284f39833421cc9b8f400a`.

**Конфигурация:** те же 773 чанка 1000/150, 142 вопроса dev, 50 кандидатов одного языка и основной бюджет 2048. BM25 Okapi: `k1=1.2`, `b=0.75`, IDF `ln(1+(N-df+0.5)/(df+0.5))`; вклад термина `IDF * tf*(k1+1)/(tf+k1*(1-b+b*dl/avgdl))`. Статистика частот и средней длины независима для RU/EN. NFKC → casefold → `ё→е` → Unicode-буквы/цифры. Без стемминга и стоп-слов, повторения термов запроса не усиливают вес. Нулевые результаты исключаются; ties — chunk ID ascending. Во всех 142 выдачах оказалось по 50 ненулевых кандидатов.

Параметры и IDF сверены с [официальной документацией Lucene BM25Similarity](https://lucene.apache.org/core/10_3_1/core/org/apache/lucene/search/similarities/BM25Similarity.html). Это собственная компактная реализация на стандартной библиотеке с точными длинами текстов, без Lucene analyzer и квантования norms. Для текущего корпуса достаточно сканирования частот всех чанков одного языка; масштабирование на большие корпуса не проверялось.

Embedding-модель не загружается, Qdrant не открывается. Загружается только локальный токенизатор BGE-M3 закреплённой ревизии для неизменного бюджета. Протокол, gold и политика упаковки совпадают с E0. Никаких изменений датасета или подбора параметров по test.

**Full run:** `a3f15fd4b17b4bacbf2216742d619524`, FINISHED, 142 вопроса. **Dry run:** `9d66d40623e241a5913ad87bd88e3221`, 3 вопроса. Прочитана одна трасса `tr-32ce732758a54d8b7739e4c4eea7bf07`: `bm25_retrieval` CHAIN → `bm25_search` RETRIEVER и `context_packing` CHAIN, без EMBEDDING.

### Парные изменения и неопределённость

По CER у RU **9 улучшений и 7 ухудшений**, у EN **5 улучшений и 4 ухудшения**. Остальные вопросы сохранили бинарный CER, при этом частичное покрытие могло измениться.

Paired bootstrap: 2000 повторов, seed 42, выборка из 71 ситуации с возвращением, RU/EN каждой ситуации сохраняются вместе. 95% percentile CI для разницы CER: **RU [−8,45; +12,68] п.п., EN [−7,04; +9,86] п.п.** Оба интервала включают ноль: уверенное превосходство BM25 не установлено. Эти интервалы не учитывают возможные ошибки разметки и зависимость тематически похожих ситуаций.

### Примеры из сохранённых выдач

Это изменения полноты размеченного текста; ответы LLM не генерировались.

- **FR018 RU, мяч лопнул при движении вперёд во время пенальти до касания игрока/стоек:** coverage 0% → 100%, CER 0 → 1. Нужный фрагмент страницы 56 RU присутствовал в обоих пулах 50, но только BM25 выбрал его в основной контекст.
- **FR017 EN, мяч лопнул в обычной игре:** coverage 0% → 100%, CER 0 → 1. Размеченный фрагмент страницы 56 EN вошёл в контекст BM25; в Dense он оставался за пределами упаковки.
- **FR001 RU, часть мяча ещё нависает над боковой линией:** coverage 100% → 0%, CER 1 → 0. BM25 не включил нужный текст страницы 103 RU в контекст, хотя он был среди 50 кандидатов.
- **FR014 EN, размеры ворот и точки измерения:** coverage 100% → 0%, CER 1 → 0. Нужный текст страницы 50 EN был в обоих пулах, но не попал в контекст BM25.

Таким образом, разные методы удачно ранжируют разные вопросы. Это основание **проверить** RRF, без гарантии улучшения hybrid. Самостоятельный BM25 не заменяет Dense по одному небольшому среднему приросту.

### Воспроизводимость и проверки

- Команда: `uv run python scripts/evaluate_retrieval.py --strategy bm25`. Dry run: добавить `--limit 3 --verify-trace`.
- Native MLflow dataset переиспользован; совпадение inputs/expectations, протокола, хешей корпуса, сценариев, evidence и cleaned pages проверено при чтении артефактов E0/E1.
- Для всех 142 контекстов E0 и E1 повторный подсчёт отдельным AutoTokenizer совпал с сохранённым числом токенов. Все основные и диагностические бюджеты соблюдены.
- В run сохранены `index-manifest.json`, код, корпус, `uv.lock`, `evaluation-protocol.json`, трассы, `summary.json`, `per-question-results.json`. В `comparison/` — сравнение, bootstrap и использованный скрипт offline analysis. Это анализ сохранённых выдач, без повторного retrieval.
- 70 тестов прошли, включая ручной расчёт BM25, Unicode/числа/отрицания, независимость языковых статистик, ties, пустую выдачу и неверные входы. Ruff/Black, strict mypy и source validator прошли. Прежнее предупреждение SQLAlchemy не подавлялось.

**Решение:** оставить E0 контролем и перейти к E2 — Dense50 + BM2550 → RRF, с прежним бюджетом 2048. Reranker, Gemini, Ragas и test в E1 не запускались. Gold остаётся автоматически подготовленным и содержит широкие evidence; CER не равен точности будущих ответов.

## Как добавлять следующий результат

Для каждого опыта добавить строку в общую таблицу и раздел: гипотеза → точная конфигурация и контрольный run → метрики RU/EN → абсолютная разница в процентных пунктах / секундах → примеры улучшений и ухудшений → ограничения и решение. Разницу считать только при одинаковом gold, evaluator, бюджете и совместимом измерении времени. Пересчёт сохранённых выдач маркировать как offline analysis, не новый inference latency.
