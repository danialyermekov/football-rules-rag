Здесь после каждого законченного опыта фиксируются конфигурация, MLflow run, метрики, изменения относительно контроля и вывод. Подробные кандидаты, тексты, диапазоны, оценки вопросов и трассы хранятся в MLflow. Не сравниваем разные версии gold/evaluator как улучшение поиска.

Основной MLflow experiment: `football-rules-retrieval`. Локальный backend: `data/mlflow/mlflow.db`. [План опытов](retrieval-experiments.md), [определения v2](retrieval-evaluation-v2.md).

## E0 — dense baseline с оценкой объединённых evidence

**Цель:** зафиксировать контроль для последующих опытов, не менять метод поиска. [Выборочный аудит разметки](evidence-audit-e0.md): 12 ситуаций / 24 языковые версии. Датасет не изменён.

**Конфигурация:** BGE-M3 ревизии `5617a9f61b028005a4858fdac845db406aefb181`, 1024-d normalized embeddings, cosine, фильтр языка, Qdrant Local, коллекция `football_a71631f65a6ba8bd0978b14e`, 773 чанка. Recursive splitter 1000/150 символов, без перехода между страницами. CPU float32 / 4 потока. CUDA-сборка PyTorch не установлена, GPU для E0 не использовался.

**Оценка:** `evidence_union_v2.0.0`, 142 вопроса / 71 dev-ситуация, по 71 вопросу RU и EN. Все locators обязательных evidence соединены AND, threshold 80%, дополнительно strict 100%. Бюджет 2048 токенов tokenizer BGE-M3 включает подписи источников; целые чанки, пропуск не поместившихся, без обрезания. Это не Gemini token usage.

**Full run:** `7c739293e3284f39833421cc9b8f400a`, статус `FINISHED`. Основная native evaluation — около 86 секунд; отдельный расчёт дополнительных диагностик и запись артефактов заняли дополнительное время и не входят в задержку запроса.

**Подтверждённый dry run:** `a452efe5d19b4285a42508796cdf77ec`, 3 вопроса. Прочитана трасса `tr-9afcb550903326986ebfe14cf6bb0bf7`: CHAIN, RETRIEVER, EMBEDDING и context packing. Более ранний dry run `fcf68f8e42ad4dc7a4a24fee32d16401` относится к промежуточной подготовке датасета и не используется как контроль.

### Проверки сохранённого результата

- Из MLflow повторно прочитаны 142 записи, статус FINISHED, 71 уникальная ситуация и по 50 кандидатов.
- Все основные контексты укладываются в 2048, а диагностические — в свои бюджеты.
- Сохранённые per-question оценки совпадают со средними native scorer в MLflow.
- Покрытие пула монотонно при расширении 10 → 20 → 50; числовые offsets из другой страницы/документа не смешиваются.
- Native dataset v2 не содержит chunk IDs в gold; его смысловые входы не зависят от разбиения.
- Валидатор исходных хешей/диапазонов датасета прошёл. 65 тестов, Ruff/Black и strict mypy прошли. Coverage нового модуля оценивания — 100% строк; это не доказательство качества retrieval. Два прежних предупреждения зависимостей SQLite/SQLAlchemy не подавлялись.

### Вывод и решение

E0 принят как **контроль v2**, а не как улучшение относительно v1. Основные направления следующего опыта: повысить доступность evidence в кандидатах через lexical/hybrid и проверить порядок/упаковку. Для reranker сначала нужен CPU/GPU smoke benchmark и сравнение с dense на точно таком же размере пула. Текущие кандидаты показывают запас, но не обещают величину выигрыша.

Gold содержит широкие фрагменты и неполные альтернативы. CER означает полноту этих размеченных текстов, а не экспертно подтверждённую минимальную достаточность ответа. Test, Gemini, Ragas, BM25 и reranker в E0 не запускались.

## Как добавлять следующий результат

Для каждого опыта добавить строку в общую таблицу и раздел: гипотеза → точная конфигурация и контрольный run → метрики RU/EN → абсолютная разница в процентных пунктах / секундах → примеры улучшений и ухудшений → ограничения и решение. Разницу считать только при одинаковом gold, evaluator, бюджете и совместимом измерении времени. Пересчёт сохранённых выдач маркировать как offline analysis, не новый inference latency.
