# Q2 — сравнение существующих метрик с разметкой Q1

Дата: 31.10.2026. Вторичный диагностический анализ уже просмотренных 48 ответов Q1, не новая оценка генерации, не эксперимент по улучшению judge и не независимая калибровка. Протокол написан до расчёта сводной confusion matrix, но после Q1, включая разбор отдельных кейсов и их scores. Следовательно это post-hoc exploratory analysis, без подтверждающих выводов и без подбора порога.

## Вопрос

Могут ли сохранённые Faithfulness и Factual Correctness при простых порогах служить единственным автоматическим фильтром существенных дефектов? Q1 определяет `critical_error` как неверное существенное решение, actor, санкцию или противоречие; пропуск обязательной санкции также мог получить этот флаг. Это субъективная аннотация coding assistant, не экспертный gold.

## Популяция и labels

Использовать primary Phase A reviews по закреплённым блокам Q001–Q016 reviewer1, Q017–Q032 reviewer2, Q033–Q048 reviewer3; запись Q1 содержит и 6 пересечений, не учитывать их как новые объекты. Исключить Q017 из-за разногласия о существенной ошибке и Q020/Q047, у которых `decision_correct=null`: качество отказов не бинаризовать как правильное или неправильное. Сохранить эти исключения; анализировать random и targeted отдельно и вместе только как составную convenience выборку. RU/EN и ответы разных моделей для одного сценария не независимы. Null applicability не превращать в успех.

`actual_bad=critical_error`. Для каждого исходного score (faithfulness, factual_correctness), только пороги **1.0** и **0.8**, одинаковые для обеих метрик: `predicted_bad = score < threshold`. 0.8 и 1.0 выбраны как диагностические срезы высоких scores из предыдущего Q1, не принятый operational quality gate. Проверить TP/FP/FN/TN, sensitivity и specificity; знаменатели и ID каждого случая вывести. При нулевом знаменателе метрику не вычислять. Высокий Faithfulness не обязан обнаруживать неполноту; поэтому confusion matrix сравнивает **разные конструкты** и не является валидированной точностью каждого scorer.

## Ограничения и результат

Не считать результат независимой точностью, преимуществом моделей или CI: 45 объектов с зависимыми контекстами/сценариями, выбранная targeted группа и исходные reviews теми же AI-рецензентами. Исторические Ragas оценки/caches, test, gold и references не изменять; новые API/generation/embeddings не выполнять. Результат и точные case IDs сохранить в проекте и в отдельном MLflow analysis run. Native genai evaluate не запускать повторно: это postprocessing existing saved values and annotations, не новая automated evaluation. Без экспериментального нового judge не заявлять роста качества измерения.
