# Консервативная очистка текста

## Задача этапа

Подготовить отдельное представление текста для будущего chunking, не изменяя исходный текст и координаты evidence в датасете. Очистка работает с результатом ingestion, без LLM, API и новых runtime-зависимостей.

```powershell
uv run football-rules clean
# Необязательные пути:
uv run football-rules clean --input data/processed/pages.jsonl --output data/processed/cleaned-pages.jsonl
```

Входной файл не перезаписывается. Все страницы обрабатываются до записи; результат заменяется атомарно. Ошибка обработки или замены файла сохраняет предыдущий результат.

## Правила обработки

1. Сверить `text` с нормализацией `raw_text`: `" ".join(raw_text.split())`. При несовпадении остановиться, чтобы не создавать неверные координаты.
2. Найти диапазоны каждой строки в исходном `text`.
3. Удалить целые строки колонтитулов по строгому шаблону: название книги, сезон, разделители `|` и название раздела. Поддерживаются наблюдавшиеся варианты `L aws` и `2026/2 7`.
4. Удалить отдельное число только на первой/последней непустой строке и только при совпадении с `printed_page`, определённым ingestion. Остальные числа остаются.
5. Соединить переносы строк пробелом. Разделять предварительные блоки по пустым строкам, маркерам `•`, номерным и нескольким известным заголовкам, завершённым предложениям. Вложенность `•` оценивать по исходному отступу.
6. Соединять слово без пробела только при явном мягком переносе U+00AD в конце строки и букве в начале следующей. Обычные дефисы и подозрительные пробелы внутри слов не исправлять.
7. На страницах с распознанным заголовком `Summary table` / `Сводная таблица` сохранять строки без попытки восстановить ячейки.

Это эвристическая группировка, ещё не chunking. Блок не обязан соответствовать полному пункту правила. Никакие слова, отрицания, условия или исключения намеренно не перефразируются.

## Формат результата

Каждая строка JSONL сохраняет все поля исходной страницы и добавляет:

| Поле | Назначение |
|---|---|
| `cleaned_text` | Текст блоков, разделённых пустой строкой |
| `blocks` | Блоки с `kind`, `text`, `list_level`, `source_spans` |
| `source_spans` | Список диапазонов `[start, end)` в исходном поле `text`, в символах Python Unicode |
| `removed_spans` | Удалённые диапазоны исходного `text` и причина удаления |
| `cleaning_flags` | Причины для дополнительной проверки |
| `cleaning_version` | Версия правил очистки |

`source_spans` находятся внутри каждого блока. Они указывают на исходные строки, а не на позиции в `cleaned_text`: переносы и форматирование списков меняют длину очищенного представления. При будущем chunking нужно переносить эти ссылки в чанки, чтобы сопоставлять retrieval с evidence через исходные координаты. Нельзя применять `char_start`/`char_end` датасета непосредственно к `cleaned_text`.

Пример исходного фрагмента:

```text
98
• Все остальные игроки (обеих команд) должны оставаться
на расстоянии не менее 4 метров (4,5 ярда) от мяча, пока он не войдет
в игру
Мяч в игре, когда он касается земли.
```

Очищенное представление:

```text
• Все остальные игроки (обеих команд) должны оставаться на расстоянии не менее 4 метров (4,5 ярда) от мяча, пока он не войдет в игру

Мяч в игре, когда он касается земли.
```

## Проверка на локальном корпусе 2026/27

Обработаны 514 страниц EN/RU. SHA-256 входного `pages.jsonl`: `fcdf2ef604a70b564947969ad92e70138fae429bb4a1979bf259b1217df52ade`.

Получены 3528 предварительных блоков. SHA-256 `cleaned-pages.jsonl`: `7cea405ef76c0939833b41566180690503d23ef71d89155b7c405893a7baa261`.

| Изменение | EN | RU | Всего |
|---|---:|---:|---:|
| Удалённые строки колонтитулов | 104 | 100 | 204 |
| Удалённые отдельные номера страниц | 219 | 189 | 408 |

Флаги: 186 страниц с растровыми изображениями, 147 с исходным текстом короче 200 символов, 5 с распознанным заголовком таблицы, 2 с неразрешённым дефисом на конце строки. Это технические признаки, а не полная разметка таблиц и иллюстраций.

Тесты проверяют сохранение всех исходных полей и учёт каждого непробельного символа на всех 514 страницах. Текст каждого блока сопоставляется с его исходными диапазонами с учётом нормализации пробелов. Отдельно проверяются отрицания, числа внутри текста, RU/EN-колонтитулы, вложенные списки, обычные/мягкие дефисы, пустые страницы, детерминированность и сохранение предыдущего результата при ошибках. Локальный интеграционный тест пропускается, если `pages.jsonl` отсутствует.

Проверки evidence исходного датасета и dev-диапазонов остаются на неизменном `text`. Полное покрытие символов подтверждает отсутствие необъяснённой потери текста, но не доказывает правильность границ каждого блока. Качество retrieval на этом этапе ещё не измеряется.

## Ограничения

- Нет восстановления столбцов, таблиц, геометрии страницы, OCR и понимания изображений. Текст, потерянный при PDF extraction, очистка не восстановит.
- Распознаются только указанные формы заголовков таблиц; остальные таблицы могут остаться без флага. Даже страницы без растровых изображений могут содержать векторные схемы.
- Границы абзацев, заголовков и уровни списков эвристические. Сокращение с точкой может создать лишний блок, неизвестный заголовок — слиться с абзацем. Исходные ссылки при этом сохраняются.
- Не исправляются `недисциплиниро ванного`, типографические ошибки и обычные переносы вроде `inter- national`: автоматическое исправление может изменить смысл.
- Нет склейки правил между страницами и присвоения иерархии Law → section. Это отдельное решение для этапа chunking, которое предстоит оценить на dev-наборе.
- Ручная проверка выполнена выборочно по текстовым примерам, а не по всем страницам PDF.
