# Ingestion: постраничное извлечение PDF

Этап выполнен 22 октября 2026 года. Результат — локальный корпус страниц с исходным извлечённым текстом, нормализованным текстом и метаданными. Chunking, поиск и вызовы генеративной модели в этот этап не входят.

## Как устроен компонент

`source-manifest.json → проверка файла → pypdf → все страницы → pages.jsonl`

Реализация находится в `src/football_rules/ingestion.py`, консольная команда — в `src/football_rules/__init__.py`.

- `load_sources()` проверяет обязательные поля manifest и уникальность ID документов.
- `extract_document()` проверяет размер, SHA-256 и число страниц PDF, затем извлекает каждую страницу. Извлечение идёт из тех же байтов, для которых проверен хеш. Зашифрованные PDF не поддерживаются; ошибки парсинга не подавляются.
- `ingest()` обрабатывает все источники до записи результата, затем сохраняет UTF-8 JSONL с LF через временный файл и атомарную замену. При ошибке извлечения прежний результат остаётся целым. Запись поверх manifest или одного из PDF запрещена.

Manifest задаёт источник, редакцию и язык; компонент не определяет их по догадке из текста. Пути PDF должны быть относительными и оставаться внутри переданного корня проекта. CLI передаёт текущую рабочую директорию, поэтому запускать его следует из корня репозитория.

## Выбор парсера

Использованы `pypdf==6.21.2` и `fonttools==4.67.0`, зафиксированные в `pyproject.toml` и `uv.lock`. Эти версии воспроизводят текст, на котором размечены доказательства датасета. FontTools нужен для разбора шрифтов некоторых исходных страниц. Временные окружения для проверки PDF перенесены в воспроизводимые зависимости приложения; новая отдельная venv не создавалась.

Это первый baseline парсинга, а не утверждение о превосходстве pypdf над PyMuPDF. Замена парсера позднее потребует проверить координаты и сохранность положений. [Официальная документация pypdf](https://pypdf.readthedocs.io/en/6.21.1/user/extract-text.html) описывает `extract_text()`, visitor-функции и ограничения извлечения текста, таблиц и изображений.

## Формат страницы

Каждая строка `data/processed/pages.jsonl` — отдельный JSON-объект:

| Поле | Смысл |
|---|---|
| `document_id`, `language`, `edition` | ID источника, язык и редакция из manifest |
| `publisher`, `source_url`, `source_sha256` | Происхождение и точная версия PDF |
| `pdf_page` | Физическая страница PDF, начиная с 1 |
| `printed_page` | Число, распознанное в нижнем поле страницы, либо `null` |
| `printed_page_method` | `footer_heuristic` либо `not_determined`; это не гарантированная семантическая метка PDF |
| `raw_text` | Текст, который вернул pypdf, с его переносами и порядком |
| `text` | `' '.join(raw_text.split())`, совместимое с координатами датасета |
| `raster_image_count` | Количество найденных растровых изображений, включая оформление и логотипы |
| `flags` | Эвристические признаки для проверки; страницы не удаляются |
| `extractor` | Имя и версии pypdf и FontTools |

`raw_text` — не буквальное внутреннее представление PDF: парсер уже преобразовал его в строки. В `text` меняются только пробельные последовательности. Колонтитулы, разорванные слова, подписи и номера в теле текста пока остаются. Автоматическое исправление переносов и удаление колонтитулов намеренно отложены, чтобы не менять содержание и координаты до проверки.

## Определение печатной страницы

В этих PDF нет `/PageLabels`, надёжно соответствующих печатным номерам. Номера ищутся среди целых положительных чисел в нижних 7% высоты и внешних 20% ширины листа. Координаты текстовых фрагментов получаем через visitor pypdf с учётом матриц преобразования.

Такое положение проверено на текущей вёрстке IFAB. Для других макетов, поворотов страниц или смещённых полей эвристику нужно проверить заново. Если кандидатов нет или несколько разных, номер остаётся `null`; физический номер PDF всегда сохраняется.

На русских PDF-страницах 129 и 131 число 7 из сезона в колонтитуле извлекается отдельным фрагментом. Проверка внешних углов позволяет отличить его от настоящих номеров 127 и 129. Этот случай воспроизведён в синтетическом тесте: число в середине нижнего поля не принимается за номер страницы.

Нельзя предполагать постоянное смещение нумерации между языками. Например, EN PDF 98 и RU PDF 100 имеют печатный номер 98, но в конце русского файла встречается иная разница.

## Признаки для проверки

- `no_text`: нормализованный текст пустой.
- `short_text`: текст непустой, но короче 100 символов; это технический порог, не оценка важности.
- `printed_page_not_found`: нет кандидата на печатный номер.
- `printed_page_ambiguous`: несколько разных кандидатов.

Отсутствие флагов не доказывает качество извлечения. Векторные рисунки могут вообще не появляться в `raster_image_count`, а их подписи могут дать достаточно текста, чтобы не сработал `short_text`. Поэтому нельзя автоматически считать страницу обычным текстом или удалять её по одному из этих полей.

## Полученный результат

| Показатель | EN | RU |
|---|---:|---:|
| Сохранено страниц | 260 | 254 |
| Без извлечённого текста | 3 | 3 |
| Непустой текст короче 100 символов | 70 | 55 |
| Печатный номер не определён | 27 | 27 |
| Неоднозначный печатный номер после исправления | 0 | 0 |
| Страницы с растровыми изображениями | 82 | 104 |

Итого 514 записей. Нулевые текстовые страницы — физические 2, 3 и 42 в обоих файлах; они сохранены. Число страниц с растровыми изображениями не является числом содержательных схем.

Нормализованный текст **514/514 страниц** совпал с зафиксированным локальным снимком `reference-pages.json`. Для development-части сохранены все **67 необходимых единиц доказательств / 141 диапазон символов** на двух языках; совпали хеши фрагментов и печатные номера их страниц. Это проверка сохранности разметки, а не вычисление качества retrieval или LLM. Вопросы test не использовались для настройки извлечения.

Хеш итогового `pages.jsonl` после запуска: `fcdf2ef604a70b564947969ad92e70138fae429bb4a1979bf259b1217df52ade`. Все исходники и результаты с текстом исключены из Git.

## Выборочная визуальная проверка

Отрисованы и просмотрены семь страниц PDF; текст сравнен с результатом извлечения:

| Страницы | Наблюдение и следствие |
|---|---|
| EN 98, RU 100 | Пункты процедуры спорного мяча присутствуют и идут в читаемом порядке. Иерархию списка отдельными структурными объектами пока не представляем. |
| EN 138, RU 143 | Текст сводных таблиц извлечён, но строки и столбцы представлены последовательно. Семантическая связь ячеек не восстанавливается; такие таблицы нельзя считать готовой структурированной справкой. |
| EN 117, RU 119 | Схемы игры рукой представлены подписями; сами формы, цвета и стрелки в тексте отсутствуют. Оба рисунка векторные, `raster_image_count=0`, текст длиннее порога short_text. Автоматические признаки их не выявляют. |
| RU 131 | Настоящий печатный номер 129 определён корректно; отдельная цифра из сезона не принята за номер. В исходном извлечённом тексте остались артефакты переноса слова в заголовке. |

Полный визуальный аудит 514 страниц не выполнен. Совпадение со снимком доказывает воспроизводимость текста, но не его семантическую полноту. OCR, распознавание векторных схем, восстановление таблиц и разметка границ правил не реализованы.

## Запуск и проверки

Из корня проекта:

```powershell
uv sync --locked
uv run football-rules ingest
uv run python -m unittest discover -s tests -v
```

Команда печатает отчёт о документах, флагах и SHA-256 результата. Повторный запуск на тех же файлах с теми же версиями должен давать тот же результат; время запуска не включается в записи.

Тесты проверяют извлечение на небольших PDF, пустые страницы, неоднозначную нумерацию, кириллицу в JSONL, неверный хеш/число страниц, пути источников, запрет перезаписи входов и повторяемость результата. Два локальных интеграционных теста проверяют весь сохранённый корпус и development-доказательства; без `pages.jsonl` и снимка они пропускаются. Они не запускают извлечение автоматически: перед ними нужно выполнить команду ingestion.

Строгая проверка типов применяется к коду приложения; форматирование и lint — к добавленным файлам. Старый датасет и его разбиение не менялись.

В текущем окружении прошли 17 тестов: 7 существующих проверок датасета, 8 тестов ingestion на синтетических PDF и 2 локальные интеграционные проверки. Покрытие строк модуля ingestion — 95% по pytest-cov. `mypy --strict` прошёл для двух файлов приложения; Black и Ruff — для кода приложения и нового файла тестов. `uv sync --locked` и реальная CLI-команда выполнены успешно. Повторный полный запуск дал тот же SHA-256 корпуса.

## Что разбираем перед следующим этапом

Нужно понять разницу между PDF-страницей и печатной страницей, между `raw_text` и `text`, и почему извлечение подписей ещё не означает понимания схемы. Затем согласуем простую стратегию chunking с сохранением привязки к исходным страницам. Обработку сложных таблиц и визуальных страниц нельзя молча считать решённой при переходе к поиску.
